## Security meaning — do not conflate these controls

**Config** means the saved value may be read back by members/API principals with appropriate project access. **Secret** means the saved value is write-only after save (while deployments can still receive it). Neither classification by itself makes a value accessible to anonymous web visitors. **Project access** controls who can manage/read configuration in Vercel; **public internet exposure** requires a separate leak or client/server behavior and was not established here. **Application authorization** is independent: Preview currently relies on Vercel Deployment Protection/SSO at the edge, and the private runtime requires a backend bearer token. Changing Config to Secret will not fix an unauthenticated route or clear a Google Safe Browsing flag by itself. Secrets are still available to code at build/runtime; avoid frontend prefixes, logs and unsafe error reflection.
