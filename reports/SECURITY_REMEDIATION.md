## Stage 4 — transactional adapter is component-tested, not operational

A dedicated PostgreSQL service is the smallest proposed managed coordinator for mission+queue transactions, fenced claims, one-time approved activation, hash-chained timeline and attempt-scoped memory. `postgres_coordinator.py` implements this **separate** native API; `migrations/001_postgres_coordinator.sql` is a *manual owner-approved migration*, not something run on an account in this session. Seventeen integration cases passed on an isolated real PostgreSQL 18.6 server. They include 16 concurrent worker claims, crash rollback, stale-heartbeat fencing/no automatic requeue, duplicate submissions, competing approval activation and uncertain COMMIT. The local full suite passed **2,612 with 6 Windows-only skips**. Existing audit/output/approval policy checks remain required; an audit event ID or DB lock alone does not authorize a tool or prove an external side effect exactly once.

**BLOCKED:** The adapter is not wired into file-based `MissionController`, checkpoint or execution audit/memory code, and no dedicated Scout coordinator or authorized Preview credential has been confirmed. Two visible Supabase projects have other/non-specific names; neither was touched or assumed available. No Vercel project/Production setting or value changed. Hosted HTTP stateful routes remain 503 and the worker remains paused, even if a DSN is set. See [`docs/POSTGRES_COORDINATOR_PLAN.md`](../docs/POSTGRES_COORDINATOR_PLAN.md) for exact least-privilege schema/Secret/scoping, backup, namespace migration, managed-fault-test, rollback and owner approval gates. Do not treat local database integration tests or CI as a live workflow demonstration.

## Files changed and why

- `autonomous_agent/vercel_proxy.py`: opaque expiring fallback sessions; immutable no-store/security headers; canonical resource IDs.
- `autonomous_agent/server.py`: bounded safe storage-error responses and request validation; direct-runtime security headers; partial mission UI; escaped persisted result and current-attempt memory; strong public-bind token check.
- `autonomous_agent/task_completion.py`, `execution_engine.py`, `task_intent.py`, `tool_router.py`: requested-output criteria independent of tool success, validated extractive facts and audit-backed replay; negative instructions are excluded from keyword routing without bypassing authorization.
- `autonomous_agent/mission_control.py`: write-before-enqueue for activation/resume; fail closed on orphan/stale items; attempt-fenced result/DAG/memory writes; bounded validated output, partial lifecycle, redacted mission text, synchronized timelines, unique approval proposals.
- `autonomous_agent/approved_executor.py`: one-time approval claim on a single host; hosted/Blob-configured claim refused before making a marker.
- `autonomous_agent/action_queue.py` / `autonomous_agent/approval.py`: corrupted approval state and stale/nonpending approvals fail closed.
- `autonomous_agent/cross_project_memory.py` / `autonomous_agent/persistent_memory.py`: strict persistence/read availability and per-mission-attempt episode identity.
- `autonomous_agent/action_queue.py`, `task_queue.py`, `background_worker.py`, `approved_executor.py`: explicit approval capacity/identity; stale worker completion fences; conservative authorization boundary.
- `autonomous_agent/filesystem_workspace.py`: deny private runtime/dotenv paths and redact token-bearing read content.
- `autonomous_agent/vercel_state.py`, `file_lock.py`, `runtime.py`, `server.py`: retain branch-specific Preview key mapping but **disable** the unsafe Blob lease path. Hosted/Blob-configured locks and direct execution refuse, workers pause, stateful APIs/health return 503; no new Blob I/O or background local fallback. The old lease code's forensic interleavings are captured in tests, not re-enabled.
- `tests/test_completion_contract.py`, `tests/test_state_invariants.py`, `tests/test_security_remediation.py`, `tests/test_vercel_state.py`, `tests/test_local_mission_e2e.py`: red/green acceptance, race, private workspace, fake-Blob and actual local authenticated HTTP two-fact canary regressions.
