## Reproduction and regression evidence

Before the changes, `tests/test_security_remediation.py` produced **10 failures** for raw/never-expiring cookies, cache policy, approval/resume queue races, orphan execution, partial resume and closed HTTP connections. Further isolated red tests reproduced cross-instance timeline/approval-claim failures, stale-local state resurrection, lost-lease deletion/write, secret-bearing mission metadata, encoded resource IDs, false project-summary VERIFIED results, duplicate approval IDs, corrupt memory/approval state, and expired/blocked/undated approval acceptance. Each relevant focused test passed after its corresponding change. These are synthetic, confined to temporary workspaces/fake Blob; no real credentials, production actions or cloud state were used.

**Latest local validation at report drafting:** locked-dependency full suite **2,557 passed, 6 skipped** (Linux; 6 Windows-only skips) in 26.80 s; focused approval, Blob, gateway, HTTP and mission regressions passed. The exact final branch commit/CI runs are recorded in `E2E_VALIDATION.md` after publication. `pip-audit` using PyPI checked 44 resolved package records with **0 known advisories** (42 pinned lines in `requirements.lock`; warning: no hashes). Bandit found **0 high, 2 medium** (expected `0.0.0.0` binds in gateway/web connector), 23 low in the final scan; Ruff reports repository-wide style/lint issues rather than a clean static-analysis pass (917 findings in the final scan, including legacy and some changed-file warnings; see validation report). Local Docker was unavailable; build checks require GitHub Actions on the review PR. Do not equate a passing test suite or audit database result with site safety.

- `autonomous_agent/vercel_proxy.py`: opaque expiring fallback sessions; immutable no-store/security headers; canonical resource IDs.
- `autonomous_agent/server.py`: bounded safe storage-error responses and request validation; direct-runtime security headers; partial mission UI; quoted-attribute escaping; strong public-bind token check.
- `autonomous_agent/mission_control.py`: write-before-enqueue for activation/resume; fail closed on orphan items; broaden no-false-success synthesis check; correct partial lifecycle; redact mission text; synchronize timelines; honest memory-failure status; unique approval proposals.
- `autonomous_agent/approved_executor.py`: cross-instance durable one-time approval claim.

- `autonomous_agent/cross_project_memory.py` / `autonomous_agent/persistent_memory.py`: strict persistence/read availability for mission episode and recall.
- `autonomous_agent/vercel_state.py`: branch-specific Preview state keys with legacy candidate compatibility, local-state resurrection guard and best-effort lease ownership checks.
- `tests/test_security_remediation.py`, `tests/test_vercel_state.py`, `tests/test_local_mission_e2e.py`: red/green regressions, cross-instance fake Blob, and actual local authenticated HTTP read-only mission canary.

- `README.md`, `docs/DEPLOYMENT_VERCEL_SERVICES.md`, `docs/DEPLOYMENT_VERCEL_AZURE.md`, `reports/*.md`: correct stale deployment/auth/durability claims and record dated evidence, limitations and an owner-gated migration.

## Residual release blockers and safe next steps

1. **BLOCKED — Google:** Exact host still unsafe. Search Console Security Issues samples/review state require verified owner access; see `SAFE_BROWSING_STATUS.md`. Do not submit duplicate reports while an owner request may be pending.
2. **BLOCKED — Vercel credentials:** Owner must approve the exact provider-supported Secret/scoping/rotation plan in `VERCEL_ENVIRONMENT_AUDIT.md`; especially do not edit an integration-managed Blob variable or revoke a credential while old deployments use it.
3. **BLOCKED — live Preview:** Authenticated browser mission, approvals, Blob persistence, runtime replacement and safe runtime-log checks were not possible with the available session. An unauthenticated SSO redirect and READY metadata do not satisfy end-to-end verification.
4. **PARTIALLY VERIFIED — Preview isolation:** New review-branch code isolates non-candidate Preview branches and preserves the candidate's existing legacy `preview/` history. Older deployed code still uses the shared legacy prefix, the current flagged deployment has not received this patch, and a future candidate namespace migration requires owner-approved backup/freeze/reconciliation. Do not run consequential missions across old/new Preview deployments until old URLs/workers are retired and real Blob isolation is tested.
5. **UNRESOLVED — distributed correctness:** The Blob SDK used here lacks conditional delete/overwrite; owner tags are a guard, not a fenced lease. There is no heartbeat for >600-second RUNNING tasks; a second runtime may mark an active long task recovery-required. Do not claim exactly-once side effects or multi-replica release readiness without a transactional/lease-capable store and real fault tests.
6. **UNRESOLVED — generative capability:** A configured provider route is not invocation. Implement an approved model call plus outcome-specific evidence/verification before any project review can be VERIFIED; keep `partial` meanwhile. Other natural-language intents still require postcondition-specific coverage.
7. **NOT TESTED — client security under SSO:** Preview CSRF characteristics, bypass inventory, authenticated dynamic HTML, older deployment content and browser-only failure states require an authorized browser session and owner review. Non-Preview logout is not a server-side session revocation.

No Production deployment, environment value/type change, credential rotation, Safe Browsing bypass or PR #280 merge was performed.
