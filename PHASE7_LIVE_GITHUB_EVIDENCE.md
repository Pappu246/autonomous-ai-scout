# Phase 7 — Live GitHub Evidence Adapter\n\n## Status\nPhase 7 adds a concrete read-only GitHub evidence acquisition layer for the Phase 6 post-change verification gate.\n\nAuthority boundary:\nGitHub REST GETs -> typed Phase 6 evidence -> pure Phase 6 verifier -> deterministic PASS / FAIL / BLOCKED.\n\nThe adapter does not merge, deploy, create branches, create PRs, write files, dispatch workflows, or change GitHub state.\n\n## Evidence collected\n- exact base-branch HEAD SHA for commit identity\n- pull-request state, draft/merged flags, exact head repository, branches and head SHA\n- complete pull-request changed-file list, exact commit tree metadata, and exact file bytes\n- workflow runs tied to the exact expected commit SHA\n\nSnapshot content digests are SHA-256 of the exact bytes returned by GitHub. Symlinks, submodules, binaries, renames, deleted files and oversized content remain visible to Phase 6 policy and fail closed under the default policy.\n\n## Pagination and truncation\nPull-request files and workflow-run collections are bounded to six 100-item pages. If the boundary is exhausted without an end page, the adapter marks evidence incomplete. A truncated Git tree also becomes incomplete evidence. Incomplete evidence cannot produce a Phase 6 PASS.\n\n## CI aggregation\nGitHub can expose both push and pull_request workflow runs for the same SHA. The adapter aggregates duplicate workflow names conservatively: failure-like conclusions dominate success; still-running results keep the aggregate incomplete; disallowed events are preserved; and all runs are bound to the requested SHA.\n\n## Transport\nGitHubApiClient now exposes bounded GET helpers for Phase 7: read_file_bytes_at_ref, pull_request_files, git_tree, workflow_runs. Existing mutation methods remain separate and are not invoked by the Phase 7 adapter.\n\n## Operational use\nUse GitHubPostChangeEvidenceProvider.from_env() to construct the live provider, then provider.verify(request) to collect evidence and execute the pure Phase 6 gate.\n\nverify() does not make a merge decision. PASS only means that the request has sufficient matching post-change evidence for the deterministic Phase 6 gate.\n\n## Explicit non-goals\n- automatic merging or deployment\n- automatic approval\n- branch protection configuration\n- workflow dispatch\n- credential persistence\n- a general-purpose GitHub mutation client
